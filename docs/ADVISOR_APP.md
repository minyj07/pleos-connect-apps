# 충전 도우미 앱 (Phase 2 앱 통합 · Phase 3 백그라운드 감시)

순정 내비(NaviHelper 3.0.5)와 중계 서버([ADVISOR_SERVER.md](ADVISOR_SERVER.md))를 이어서, 충전이 필요할 때
실시간 충전소 상태를 보고 추천하는 앱 쪽 구현입니다. 순정 내비 안에 기능을 넣을 수는 없으므로 앱은 내비를 읽고
(경로·남은 에너지·충전 경유지) 내비에 요청(목적지·경유지·검색 화면)만 합니다. 안내는 계속 순정 내비가 합니다.
운전 중에는 내비가 앱 영역을 차지하므로, 앱이 가려진 동안에도 감시하고 버튼 달린 알림으로 알립니다(Phase 3).

## 동작 흐름

1. 차량 상태·내비 상태·설정이 바뀌면 `ChargeNeedEvaluator` 가 필요 여부를 정합니다.
2. 필요하고 위치 전송에 동의했으면, 내비·차량 콜백이 다 들어오도록 1 s 기다렸다가 그때까지 들어온 최신 값으로 서버
   `/v1/recommendations` 를 부릅니다(예: SOC 가 주행가능 거리보다 먼저 옴). 좌표는 소수 3자리(약 100 m)로 반올림해 보냅니다.
   동의 전에는 서버를 부르지 않습니다. 경로가 아직 다 들어오지 않았거나(목적지 미수신) 내비에 충전 경유지를 묻는 중이면
   끝날 때까지 기다렸다가 한 번만 보냅니다.
3. 상위 3곳을 `requestTrip` 으로 하나씩 정밀화하고(TripInfo 에 요청 id 가 없어 목적지 좌표 500 m 이내로 짝짓기),
   같은 `StationScorer` 로 다시 줄을 세워 최대 3장을 보여 줍니다. 경로를 따라 고를 때만 20 km 구간마다 최대 2곳으로 나눕니다.
   주변 검색(`NEARBY`)은 서버처럼 나누지 않습니다(2026-11-05 전에는 나눠서 가까운 2장만 나왔음).
4. 3분마다(실패 후엔 1분) 화면의 충전소 상태만 `/v1/stations/status` 로 다시 받습니다(충전소 id 만 보내고 위치는 보내지 않음).
   카드 순서는 그대로 두고 숫자와 상태 경고("지금 빈 충전기가 없어요" 등)만 바꿉니다. 경로의 충전소가 OK 에서 만차·불명으로 바뀌거나 빈 곳이 하나도 없으면,
   또는 마지막 추천 뒤 10 km 넘게 움직였거나 15분이 지났으면 위치를 보내 추천을 다시 받습니다.
   필요·경로·충전 경유지·설정이 바뀌어도 바로 다시 받습니다. 상태 갱신이 실패한 뒤의 재시도도 충전소 id 만 보냅니다(위치는 전체 추천이 실패했을 때만).
   안내가 없을 때도 30초마다 내비에 현재 위치를 물어, 주변 검색의 출발점과 10 km 규칙이 옛 위치에 머물지 않게 합니다.
5. "경로"는 목적지(이름·좌표)로 구분합니다. 내비의 `routeId` 는 내비가 스스로 재탐색할 때마다 바뀌어서(E2E 에서 몇 분마다 관찰)
   그대로 쓰면 같은 여행을 새 경로로 보고 위치를 다시 보냈습니다.
6. 경유지를 넣거나 빼면 내비가 경로를 취소(`onRouteCancelled`)하고 8~12초 뒤 새 경로를 냅니다. 그동안(최대 20초)은 원래 경로를
   그대로 두고 판단하지 않습니다. 2026-11-05 전에는 그 틈을 "안내 끝"으로 보고, 위치를 보내 주변 추천으로 카드를 바꿨으며 SOC 8% 이하면 긴급 알림까지 띄웠습니다.

| 판단 | 조건 | 화면 |
| --- | --- | --- |
| `ON_ROUTE` | 안내 중, 경로에 충전 경유지 없음, 내비 도착 에너지(Wh ÷ 용량)가 예비 SOC 미만(해제는 +3 %p), +5 %p 이내면 참고 | "목적지 도착 시 배터리가 부족할 수 있어요" |
| `PLANNED_STOP` | 안내 중, 경로에 충전 경유지가 있거나 목적지가 충전소 → 그 충전소의 실시간 상태 확인(만차·불명이면 추천으로 올림). 설정한 최소 출력 이상인 충전기가 하나도 없으면 만차로 보지 않음 | "내비가 고른 / 경유지 / 목적지 ○○: 급속 4/5 이용 가능", "…: 설정한 출력 이상인 충전기가 없어요" |
| `NEARBY` | 안내 없음, SOC ≤ 20 % 또는 주행가능 ≤ 50 km(해제는 25 %·60 km) | "배터리가 얼마 남지 않았어요" |
| 긴급 | SOC ≤ 8 %, 주행가능 < 25 km, 내비 `CAUSE_LOW_BATTERY` | 제목·배너 빨간색 "긴급 · …" |
| 억제 | 충전 중 또는 커넥터 연결, SOC 모름 | 아무것도 하지 않음 |

예비 SOC 는 설정값과 내비 `targetSoc`(10 %) 중 큰 값입니다.

## 경로의 충전소 찾기 (`PlannedStopResolver`)

내비가 알려 주는 정차지 정보에는 좌표가 없습니다. 그래서 출처별로 위치를 찾습니다. 가는 길의 충전 경유지가 먼저이고,
없을 때 목적지가 충전소면 목적지를 점검합니다.

| 경우 | 충전소 이름 | 위치 |
| --- | --- | --- |
| `DrivingInfo` 를 받았음(경로가 바뀔 때만 옴) | 첫 번째 `isChargingStation` 정차지 | 아래 중 하나 |
| 앱 재시작 등으로 `DrivingInfo` 가 없음 | 이름에 "충전"이 있거나 앱이 넣은 수동 경유지(`WaypointInfo`) → 없으면 `requestTrip(목적지)` 의 AUTO 충전소 | |
| 가는 길에 충전소가 없고 목적지가 충전소 | 목적지. 앱이 안내한 충전소이거나, 이름에 "충전"이 있거나, `DrivingInfo` 가 목적지를 충전소로 표시 | 목적지 좌표 |
| 앱에서 넣거나 안내한 충전소 | | 넣을 때 기억한 좌표와 statId |
| 내비 검색에서 고른 경유지 | | 내비 **최근 목적지**(`getRecentDestinationInfo`)에서 poiId(없으면 이름)로 찾은 좌표 |
| 내비가 자동으로 넣은 충전소 | | `requestTrip(목적지)` 의 AUTO 충전소 중 **이름이 같은 것** |

못 찾으면 추측하지 않고 "실시간 정보를 찾지 못했어요"로 표시합니다. `requestTrip(목적지)` 는 현재 경로의 수동 경유지를
무시하고 새로 계획하므로, 수동 충전 경유지가 있을 때 대신 쓰면 엉뚱한 충전소를 점검하게 됩니다(E2E 에서 발견해 고침).
내비는 좌표로 받은 목적지를 충전소로 표시하지 않으므로(`DrivingInfo` 목적지 `isChargingStation=false`, E2E), 앱이 안내한
충전소는 이름과 statId 를 기억해 두고 알아봅니다.

**긴급할 때 갈 수 없는 충전소**: 긴급(SOC 8 % 이하 등)인데 그 충전소까지 직선 거리 × 1.3 이 주행가능 거리(없으면 SOC ÷ 소비율)보다
길면, 내비가 더 넉넉한 배터리일 때 고른 충전소로 보고 주변 충전소(`NEARBY`)를 추천합니다. 판정은 `UNREACHABLE`
("…까지 배터리가 부족해요 · 가까운 …")이고, 위치 없는 상태 갱신으로는 바꾸지 않습니다. 추천을 받은 뒤 주행가능 거리가 줄어도
앱 안에서 다시 계산하고, 갈 수 없게 되면 그때 다시 요청합니다(30초에 한 번까지).

## 카드 버튼 (`WaypointPlanner`)

| 상황 | 큰 버튼 | 정차 중 보조 버튼 |
| --- | --- | --- |
| 안내 없음 | 이 충전소로 안내(`requestRoute`, 내비가 앞으로 나옴) | 내비에서 찾아 추가 |
| 안내 중, 점검하는 충전소가 목적지 | 이 충전소로 안내(목적지 변경. 만차인 목적지로 가는 길에 들르는 것이 아님) | 내비에서 찾아 추가 |
| 안내 중, 내비 poiId 를 앎 | 경유지로 추가(충전소로 인식) | 내비에서 찾아 추가 |
| 안내 중, poiId 모름(대부분) | 내비에서 찾아 추가(`SearchPlace` + 내비 전환 → 내비 POI 화면의 "경유지로") | 좌표로 경유지 추가("내비가 충전소를 하나 더 넣을 수 있어요" 안내) |
| 안내 중, 수동 경유지 2개 | 내비에서 찾아 추가 | — |

주행 중(CarUxRestrictions)에는 스크롤 없이 카드당 이름·대기 대수·출력·우회/도착 SOC·확인 시각과 큰 버튼 하나만 보이고,
운영사·주의 문구·보조 버튼·설정은 숨깁니다. 경로 변경은 항상 운전자가 눌러야만 합니다.

### 버튼 크기와 위치 (2026-11-03)

기준은 Pleos Connect UI Design Guide 의 기본 버튼 높이 Large / Medium / Small = 100 / 80 / 64 px(아이콘 36 px)입니다. 가이드 본문에는
숫자가 없고 그림(`basic_size.svg`)에만 있습니다. Pleos 화면이 160 dpi 라 px 를 dp 로 그대로 씁니다(`ui/theme/ButtonSize.kt`).
누르는 것은 모두 64 dp 이상이고, 주행 중에도 보이는 버튼은 80 dp 이상입니다.

| 위치 | 버튼 |
| --- | --- |
| 추천 카드 | 주 버튼은 카드 맨 아래(정차 80 dp, 주행 중 100 dp). 보조 버튼(정차 중, 64 dp, 테두리)은 그 위. 카드가 나란히 있으면 높이를 맞춰 주 버튼이 한 줄에 옴 |
| 도우미 머리글 | 뒤로·새로고침 80 dp(배경 있는 원형). "내비 연결됨" 같은 상태는 버튼처럼 보이지 않는 테두리 글자(누를 수 없음) |
| 설정(정차 중) | 칩 대신 구간 선택(segmented) 64 dp, 칸 너비 160 dp. 선택된 칸은 어두운 초록 채움·옅은 초록 글자·초록 테두리(꽉 찬 초록은 실행 버튼에만 씀). "알림 허용"·"위치 전송 동의 철회"는 64 dp 테두리 버튼 |
| 대시보드 | "충전 도우미"를 머리글 오른쪽 끝(기본 40 dp)에서 게이지 바로 아래 큰 버튼(80 dp)으로 옮김. 충전 필요 배너 80 dp, "재연결" 80 dp |
| 업데이트 팝업 | "예"(채움)·"아니요"(테두리) 160 × 64 dp. 바탕은 앱의 푸른빛 짙은 회색 |

색: M3 부품은 테마(`ui/theme/Theme.kt`)에 없는 색 역할에 M3 기본값(보랏빛 회색)을 씁니다. 선택 칸은 기본값
`secondaryContainer` 대신 `primaryContainer`(#245035)를 직접 지정하고, 팝업 바탕(`surfaceContainerHigh`)이 속한
`surfaceContainer` 계열은 테마에 앱의 푸른빛 회색으로 넣었습니다(팝업 #1F2730). 새 M3 부품을 쓸 때는 어떤 색 역할을 쓰는지 확인합니다.

에뮬레이터 화면: `docs/screenshots/ui-dashboard.png`, `ui-advisor-parked.png`(SOC 8 % 긴급, 정차), `ui-advisor-driving.png`(기어 D),
`ui-update-dialog.png`(서버 `APP_LATEST_VERSION_CODE=2`로 띄운 업데이트 팝업).

정밀화 보정 두 가지(E2E 에서 발견):
- 내비는 SOC 를 배터리 잔량(kWh) ÷ 용량으로 계산하므로 차량 SOC 와 어긋날 수 있습니다. 도착 SOC 가 현재 SOC 보다 높게 오면
  차량 소비율로 다시 계산합니다.
- SOC 가 내비 최소 도착 SOC(10 %)보다 낮으면 바로 옆 충전소로 가는 `requestTrip` 에도 내비가 다른 충전소를 끼워 넣습니다.
  이때는 후보를 버리지 않고 서버 추정치를 쓰며, 서버 추정으로도 도착할 수 없을 때만 뺍니다.

서버에 연결할 수 없으면 후보가 없을 때 "충전 정보 서버에 연결할 수 없어요" + "내비 충전소 목록 보기"(순정 내비 주변 충전소
화면)를, 이전 후보가 있으면 그 위에 "마지막으로 받은 정보예요"를 표시합니다.

## 백그라운드 감시와 알림 (Phase 3)

Pleos 에서는 앱이 내비에 가려지면 1~2분 안에 프로세스가 동결됩니다(Phase 0). 그래서 `specialUse` 포그라운드 서비스
(`AdvisorService`)로 프로세스를 살려 두고, 판단은 그대로 프로세스 범위의 `ChargingAdvisor` 가 합니다. 안드로이드 12 이상은
백그라운드에서 포그라운드 서비스를 시작할 수 없으므로 앱 화면이 보일 때 시작합니다.

**감시 서비스 (`WatchPolicy`)**

| 조건 | 동작 |
| --- | --- |
| 위치 전송 동의 + "내비 화면에서도 감시" 켬 + 충전 중 아님 + 앱 화면이 보임 | 시작 |
| 안내 중이거나 충전 필요가 있거나 앱 화면이 보이는 동안, 그리고 그 뒤 10분 | 유지(앱을 연 직후·도착 직후 새 경로도 잡으려고) |
| 안내 없이 충전 시작·커넥터 연결, 설정 끔, 동의 철회 | 즉시 정지 |
| 안내 중 충전(경로의 충전소에서 충전) | 유지. 서비스는 앱 화면이 보일 때만 다시 켤 수 있어, 멈추면 충전 뒤 남은 경로를 지켜보지 못함(2026-11-05 수정) |
| 상시 알림의 "끄기" | 정지. 앱을 다시 열 때까지 켜지 않음 |

상시 알림(조용한 채널 `advisor_watch`): "충전 도우미가 경로를 보고 있어요" + "경로의 충전소 괴산휴게소(창원방향): 급속 1/8 이용 가능",
"도착할 때까지 충전이 필요하지 않아요" 같은 한 줄. 누르면 도우미 화면을 엽니다. 부팅 후 자동 시작은 하지 않습니다.

**헤드업 알림 (`AlertPolicy`, 채널 `advisor_alert`, IMPORTANCE_HIGH)**

| 규칙 | 값 |
| --- | --- |
| 알릴 주제 | 경로의 충전소 만차·전부 고장(`PLANNED_STOP`), 도착 전 충전 필요(`ON_ROUTE`, 권장 이상), 안내 없이 배터리 부족(`NEARBY`). 상태 불명인 경로 충전소는 긴급일 때만 |
| 진입 지연 | 같은 주제가 45 s 유지되고 카드(또는 실패)가 나온 뒤. 긴급은 바로 |
| 반복 | 같은 여행(목적지)·같은 주제는 15분에 한 번. 심각도가 오르면 바로(이때 "나중에"도 풀림). 긴급 주제는 사라졌다가 다시 오면 바로. 경로의 충전소 주제는 충전소마다 따로(괴산을 처리한 뒤 문경이 만차가 되면 새 주제) |
| 나중에 | "나중에" 버튼이나 알림을 밀어서 지우면 그 주제를 30분 쉼. 10분 표시 시간이 끝나 사라진 것은 쉬지 않음(시스템이 같은 삭제 인텐트를 보내서 2026-11-05 전에는 30분 쉬었음) |
| 앱이 보일 때 | 긴급만 알림(화면에 이미 카드가 있음) |
| 표시 시간 | 10분 뒤 자동으로 사라지고, 주제가 없어지면 바로 거둠. 그 사이 숫자가 바뀌면 소리 없이 갱신 |

알림 문구: 제목 "경로의 충전소에 빈 충전기가 없어요"(긴급이면 "긴급 · …"), 본문 "대안 문경휴게소(창원방향) · 급속 4/5 · +0분 · 도착 13%".
지금 빈 충전기가 있는 후보를 먼저 고릅니다. 후보가 없으면 본문은 이유("조건에 맞는 충전소를 찾지 못했어요" 등)이고 버튼은 "내비 충전소 목록"입니다.

**알림 버튼**

| 버튼 | 경로 | 결과 |
| --- | --- | --- |
| 내비에서 찾아 추가(안내 중 기본) | 투명 `NaviActionActivity` → `SearchPlace` + 내비 앞으로 → 닫힘 | 내비 검색 화면. 운전자가 POI 화면의 "경유지로"를 누름 |
| 이 충전소로 안내(안내 없음) / 경유지로 추가(내비 poiId 를 알 때) | `AdvisorActionReceiver`(non-exported, `goAsync`) | 화면 전환 없이 내비가 처리(`requestRoute` 는 내비가 스스로 앞으로 나옴) |
| 내비 충전소 목록(후보 없음) | 리시버 → `NearbyChargingStations` | 내비 충전소 화면 |
| 다른 곳 보기 / 알림 본문 | `MainActivity`(`open_advisor`, 실행 중이면 `onNewIntent`) | 도우미 화면 |
| 나중에 / 밀어서 지우기 | 리시버 | 30분 쉼 |

- "내비에서 찾아 추가"만 액티비티를 거치는 이유: 내비는 `SearchPlace` 를 받아도 앞으로 나오지 않아 앱이 내비를 띄워야 하는데,
  안드로이드 12+ 는 알림의 브로드캐스트에서 액티비티 시작을 막습니다(notification trampoline). 알림이 직접 연 액티비티는 띄울 수 있습니다.
- 버튼은 알림을 올린 때가 아니라 누른 때의 경로로 동작을 다시 정합니다(`StationRef` + `WaypointPlanner`). 예: 그새 경유지가 생겼으면 빈 칸에 넣음.
  프로세스가 새로 떴으면 내비 연결을 5 s 까지 기다립니다. 내비가 요청을 받지 못하면 알림을 그대로 두어 다시 누를 수 있습니다. 카드 버튼도 누른 때의 경로로 다시 정합니다.
- 알림 본문을 눌러도 알림을 지우지 않습니다(자동 취소를 끄면, 화면을 연 뒤 숫자만 바뀐 조용한 갱신이 소리 나는 새 알림이 되지 않음).
- 내비 화면으로 가는 투명 액티비티는 "앱이 보임"으로 세지 않습니다(그래야 "끄기"한 감시가 다시 켜지지 않음). 화면 회전·주야간 전환으로 액티비티가 다시 만들어지는 순간도 마찬가지입니다.
- 계획의 "추가됨 · 되돌리기"는 만들지 않았습니다. 알림의 기본 버튼은 내비 검색(운전자가 내비에서 마무리)과 안내 없는 상태의
  목적지 설정이라 되돌릴 대상이 없습니다.
- 계획의 "대기 0대 + ETA > 10분이면 경고 상향" 조건은 쓰지 않고 만차·전부 고장이면 알립니다(대안 판단은 운전자에게).

**권한**: `CAR_ENERGY` 는 정차 중일 때 한 번 요청합니다(권한 대화상자는 주행 중 표시 불가). `POST_NOTIFICATIONS` 는 위치 전송에
동의할 때와 도우미 설정의 "알림 허용"(알림이 꺼져 있을 때만 보임)에서 요청합니다. 알림 권한이 없어도 감시 서비스는 돕니다(알림만 안 보임).

## 설정

- 도우미 화면(정차 중): 도착 예비 배터리, 최소 충전 출력, 내비 화면에서도 감시(켜기/끄기), 알림 허용, 위치 전송 동의 철회.
- 서버 주소: `local.properties` 의 `advisor.baseUrl`(기본 `http://127.0.0.1:8080`), 릴리즈는 `advisor.releaseBaseUrl`(https 만. 비우면 서버를 부르지 않고 "충전 정보 서버가 설정되지 않았어요" 표시).
- cleartext 는 debug 빌드에서 `127.0.0.1`·`10.0.2.2`·`localhost` 만 허용합니다.
- 로그: 릴리즈는 좌표·경로를 남기지 않습니다. debug 빌드는 정차지 이름, 요청 모드, 알림 판단 입력(목적지는 해시), 내비 `routeId` 만 `PleosNaviRepo`·`ChargingAdvisor`·`AdvisorMonitor` 태그로 남깁니다.

E2E 에서 찾아 고친 것:
- 앱이 경로 도중 시작되면 내비 콜백 순서(경로 id → 목적지)에 따라 목적지 좌표 없이 충전 경유지를 물어 "없음"으로 저장 → 괴산을 놓침. 목적지 좌표가 온 뒤에만 묻도록 고침(Phase 2 부터 있던 경합).
- 그 질의가 끝나기 전에 ON_ROUTE/NEARBY 요청이 먼저 나가 위치를 두 번 보냄 → 경로가 다 들어오고 질의가 끝난 뒤 한 번만.
- 내비가 스스로 재탐색할 때마다 `routeId` 가 바뀌어 같은 여행을 새 경로로 보고 위치 재전송·알림 대기 초기화 → 경로 키를 목적지로.
- "나중에" 뒤 긴급으로 올라 다시 알린 직후, 남은 "나중에"가 알림을 0.5 s 만에 거둠 → 심각도 상승으로 알리면 "나중에" 해제.
- SOC 가 주행가능 거리보다 먼저 와서, 요청이 1 s 대기 전에 잡아 둔 옛 주행가능 거리(210 km)로 도달 여부를 판단 → 대기 뒤 최신 입력으로 요청.

확인하지 못한 것:
- **헤드업 카드 표시.** 알림은 IMPORTANCE_HIGH·카테고리 recommendation·버튼 3개로 게시되고 Pleos 헤드업 서비스(`ai.umos.notification`)가 받지만,
  이날 에뮬레이터는 카드를 그리지 않았습니다(Phase 0 프로브 알림도 같음, 재부팅해도 같음). 알림 센터도 비어 있어 버튼은 adb 로 같은 요청을 보내 확인했습니다.
  자세한 관찰은 [SPIKE_NAVI_EV.md §7](SPIKE_NAVI_EV.md). 실차 또는 Pleos 기술지원으로 확인해야 합니다.
- 충전 시작 시 감시 정지: Virtual Console 에 충전 상태(EV_CHARGE_STATE)·커넥터 연결을 바꾸는 항목이 없어 단위 테스트로만 확인.
- 경로 종료 10분 뒤 감시 정지, 주행 중(MOVING) 알림, 내비 모의주행·실차에서 위치가 움직이는 상황. (실제 data.go.kr 데이터는 2026-11-04 확인, 아래 절)

찾아 고친 것:
- ① 배터리 용량: `INFO_EV_BATTERY_CAPACITY` 는 정적 속성이라 변경 이벤트가 없습니다. 배터리 에너지 이벤트가 올 때마다 다시 읽습니다(`CarPropertySource`). 콘솔은 용량을 쓸 때 배터리 묶음을 함께 보내서, 용량 카드만 바꿔도 바로 반영됩니다.
- ② 충전 스위치: Pleos SDK 는 연결할 때 한 번만 읽습니다. AAOS `EV_CHARGE_SWITCH` 도 구독합니다(debug 로그 `AaosCarProperty: 0x11200f42 -> true`).
- ③ 주행가능 거리 오경보: 콘솔이 들고 있던 0 m가 주행 정보 묶음과 함께 들어와, SOC 100 %에서 "긴급"이 됐습니다. 그 오경보가 같은 주제 15분 반복 규칙에 걸려, 8분 뒤 SOC 7 %의 진짜 긴급 알림이 나가지 않았습니다. `Reach.usableRangeKm` 은 SOC 1 %당 0.5 km에 못 미치는 주행가능 거리(배터리 가득일 때 50 km 미만)를 판단에 쓰지 않습니다. 대시보드에는 차량 값을 그대로 보여 줍니다. 겨울철 35 kWh 차(SOC 50 %에 75 km)는 그대로 씁니다.
- ④ 충전 표시: 커넥터가 분리로 보고되면 충전 카드는 "대기"입니다. `isCharging` 도 커넥터가 분리로 보고되면 false입니다(지난 충전의 상태가 남아 충전 안내를 막지 않게).
- ⑤ 내비 도착 에너지: 내비는 경로를 잡을 때의 배터리로 도착 에너지를 계산하고, 배터리가 바뀌어도 그대로 둡니다(SOC 25 → 100 %에도 6.4 kWh, 새 경로 요청 때만 다시 계산). 배터리가 떨어진 뒤 내비 값이 현재 SOC보다 2 %p 넘게 높으면 버리고 주행가능 거리로 판단합니다(`ChargeNeedEvaluator`, 단위 테스트 추가). 충전해서 SOC가 올라간 경우는 2026-11-05에 보탰습니다: 내비 값이 들어온 뒤 가장 낮았던 SOC보다 2 %p 넘게 오르면 내비가 새 값을 줄 때까지 주행가능 거리로 판단합니다. 앱 프로세스가 그 사이 새로 떴다면 가려내지 못합니다.
- 주행가능 거리 추정이 음수일 때 "도착 예상 -109%" 대신 "도착 전 소진 예상"으로 표시합니다.

앱 단위 테스트 49 → 54개(모두 통과). 콘솔로 테스트할 때는 Remaining Range를 먼저 정하고, 배터리를 바꾼 뒤에는 내비 경로를 다시 잡습니다.
웹 화면을 연 채로 API로 속도를 넣으면 페이지의 주행 시뮬레이터가 속도를 덮어씁니다.

- 경유지로 넣은 충전소가 만차일 때 대안은 경유지로 "추가"만 하고 만차 경유지를 빼지 않습니다(빼고 넣는 순서의 내비 동작을 에뮬레이터에서 먼저 확인해야 함).
- `requestTrip` 답이 6초를 넘으면 다음 요청이 그 답을 가져갈 수 있습니다(500 m 안의 두 충전소일 때, 드묾).
- 정책 타이머가 벽시계 기준이라, 차량 시각이 크게 바뀌면 알림·재시도가 그만큼 밀립니다.
- 서버: 상태 조회 창은 문서대로 5분 고정, 한 시도가 계속 실패하면 전체 동기화를 처음부터 다시 함, 긴 전체 동기화 동안 상태 조회가 막혀 처음 몇 분의 변경을 놓침.
- 중복 정리(앱·서버의 에너지 모델, 동기화 페이지 반복, 기본값 리터럴, 쓰이지 않는 필드·메서드)는 동작을 바꾸지 않아 하지 않았습니다.
